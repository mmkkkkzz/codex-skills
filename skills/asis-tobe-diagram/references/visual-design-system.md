# Visual Design System

## 1. 目的

図の美しさより、**比較、責任、流れ、課題、変更、例外、根拠が短時間で読めること**を優先する。色だけに意味を持たせず、形、ラベル、線種を併用する。

## 2. 標準レイアウト

- 基本はAs-isを上、To-beを下に積む。
- 比較が主目的で横幅に余裕がある場合は左右配置も可。
- As-isとTo-beでレーン順と工程順を揃える。
- 左から右へ通常フローを進める。
- 例外、差戻し、再処理は下側または専用帯へ逃がす。
- システム境界、サブプロセス、対象範囲はグループ枠で表す。

### 密度の目安

- 1状態あたりレーン: 6以下
- 工程: 8以下
- ノード: 35以下
- 1ノードのラベル: 2行、概ね28文字以内

超える場合はL0概要図とL1/L2詳細図に分割する。

## 3. 情報の視覚符号

| 対象 | 表現 |
|---|---|
| 手作業 | `手動` バッジ、人型または通常処理ノード |
| 自動処理 | `自動` バッジ、システム処理ノード |
| 半自動 | `半自動` バッジ |
| 判断 | ひし形または明示的な判断ノード |
| データ | データノードとデータ線 |
| 例外 | 破線または例外ラベル付き線 |
| 統制 | `承認`, `照合`, `監査` 等の明示ラベル |
| 課題 | `P-xx` バッジと課題詳細へのリンク |
| 変更 | `C-xx` バッジと変更台帳へのリンク |
| リスク | `R-xx` バッジ |
| 未確定 | `要確認`, `仮置き` バッジ、低確度表示 |

## 4. 色

色はテーマ設定で変更できる。標準の意味は次のとおり。

- As-is: 青系
- To-be: 橙・金系
- 課題: 赤系
- KPI・効果: 緑系
- 未確定・注意: 黄系
- システム・データ: 中立色または補助色

必ずテキスト、ID、アイコン、線種を併用し、白黒印刷でも識別できるようにする。背景と文字は十分なコントラストを確保する。

## 5. タイポグラフィ

- 外部Webフォントを使わず、OS標準の日本語サンセリフを使う。
- 本文は画面上で原則12px以上、印刷時は8pt以上を目安とする。
- ノード内の長文は詳細パネルへ逃がし、図には要約を置く。
- 略語は初出で正式名称または凡例を示す。

## 6. 線と矢印

- 通常フローは最も強く、データ・例外・統制は線種を変える。
- 交差を減らし、同一経路の平行線をまとめる。
- 長距離の戻り線は図の外周を通す。
- 線の向きが曖昧にならないよう、矢印を終端に置く。
- 判断分岐には条件を付ける。`Yes/No`だけで意味が不足する場合は業務条件を書く。

## 7. 比較表現

As-is / To-beの対応関係を次で示す。

- 同じレーン・工程位置
- 安定IDと変更ID
- 変更点帯または差分一覧
- 廃止、追加、自動化、責任移管、統合、分割の種別
- 課題 → 変更 → KPIのリンク

ピクセル単位で同じ配置にすることより、意味上比較できることを優先する。

## 8. HTMLの操作性

生成HTMLには次を備える。

- ノード選択時の詳細表示
- ズーム、フィット、スクロール
- 課題、変更、KPI、リスク、質問、根拠のタブ
- JSON編集と再描画
- JSON、SVG、PNGの出力
- 印刷・PDF保存
- キーボードでの主要操作

外部CDN、解析タグ、外部フォント、外部JavaScriptを使わない。

## 9. 印刷

- 操作UIは印刷時に非表示にする。
- A3横を標準とし、簡易図はA4横でも読めるようにする。
- ページ分割でノードや見出しが欠落しないようにする。
- 背景色を印刷しない環境でもID、枠線、ラベルで意味が残るようにする。

## 10. 避ける表現

- 色だけでAs-is / To-beや課題を区別する
- 小さい文字を大量に詰め込む
- すべてを同じ四角形で描く
- 自動化を1箱に圧縮し、例外と運用を描かない
- システム名と業務処理名を混同する
- 線が重なり、どこからどこへ行くか追えない
- 根拠のない定量効果を大きく強調する
