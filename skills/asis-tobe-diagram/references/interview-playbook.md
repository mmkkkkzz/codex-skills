# Interview Playbook

## 目的

As-is / To-be図の初稿を作る前に、資料から判明していることと、意思決定に必要な不足情報を分離する。質問数を増やすことではなく、**誤ったスコープ、責任分界、統制、実装前提を早期に潰すこと**を目的とする。

## 1. まず資料から抽出する

情報源ごとに次を抽出し、同じ内容を質問しない。

- 業務の目的、開始条件、終了条件、対象外
- 関係者、担当、承認者、運用責任者
- 通常フロー、例外、差戻し、再処理
- 利用システム、帳票、データ、連携方式
- 件数、頻度、所要時間、待ち時間、エラー、再作業
- 法令、監査、権限、保存、期限、予算等の制約
- 現行課題、根本原因、既存の回避策
- To-be案、未確定事項、対立する要望

各項目を次の状態に分類する。

| 状態 | 定義 | 扱い |
|---|---|---|
| `known` | 複数の根拠または責任者の明示的回答がある | 事実としてモデル化 |
| `partial` | 一部だけ判明、条件や例外が不足 | 仮置きし、必要なら質問 |
| `unknown` | 根拠がない | ブロッカーなら質問、非ブロッカーなら未確認 |
| `conflicting` | 情報源間で矛盾 | 勝手に統合せず、対立を示して質問 |

## 2. 質問すべきかの判定

次のいずれかに該当する場合は質問する。

1. 回答によって図のスコープ、主要レーン、主要工程が変わる。
2. 回答によってTo-beの統制、責任、例外対応、安全性が変わる。
3. 回答によってAPI、ファイル連携、RPA、AI等の実現方式が大きく変わる。
4. 情報源が矛盾しており、片方を採用すると顧客合意を誤る。
5. 図の目的や読者が不明で、必要な粒度を決められない。

次は原則として質問せず、`未計測`、`仮目標`、`要確認`として初稿を作ってよい。

- 正確な件数、時間、金額、エラー率
- 未確定の製品名やサービス名
- 低頻度の詳細例外
- 画面項目、API仕様、データ型等の実装詳細

## 3. 質問群の組み立て

質問は原則1回、最大8問。重要度順に並べる。

### 推奨質問テンプレート

1. **目的・読者**
   この図で最終的に合意または判断したいことは何ですか。主な読者は経営層、業務責任者、現場、IT、ベンダーのどれですか。

2. **対象範囲**
   業務の開始条件と完了条件、今回対象外にする工程を教えてください。未回答の場合は、資料上の最初と最後のイベントを仮の境界にします。

3. **責任分界**
   主担当、承認者、例外対応者、運用責任者を確認してください。部署名ではなく役割名でも構いません。

4. **現行の実態**
   標準手順と実際の運用が異なる箇所、差戻し、手戻り、待ち、二重入力、属人対応を教えてください。

5. **To-beの必須条件**
   To-beで必ず維持する統制、法令、既存システム、期限、予算、権限制約は何ですか。

6. **連携・自動化**
   API、CSV、メール、RPA、手入力のうち利用可能または禁止の方式はありますか。連携失敗時の手動フォールバックも確認してください。

7. **例外・失敗時**
   自動処理できないケース、判断を人に戻す条件、再実行・差戻し・中断時の責任者を教えてください。

8. **効果測定**
   改善成功を何で判断しますか。現時点で数値がなければ、測定候補とデータ取得方法だけを仮置きします。

## 4. 質問の書式

各質問には次を含める。

- 既知の前提
- 質問本文
- なぜ必要か
- 選択肢または回答例
- 未回答時の仮定

例:

```text
資料上、申請者→営業アシスタント→営業担当の順に処理すると理解しています。
承認権限は金額別ですか、案件種別ですか、それとも一律ですか。
この回答でTo-beの判断ノードと監査証跡が変わります。
未回答の場合は「一律承認・詳細条件は要確認」として初稿を作ります。
```

## 5. 回答を受けた後

- 回答を情報源として `meta.sources` に登録する。
- 事実は該当ノード・エッジの `sourceIds` に紐付ける。
- 暫定回答は `meta.assumptions` に置き、責任者と期限を付ける。
- 矛盾は `meta.conflicts` に残し、解消されるまで勝手に削除しない。
- ブロッカーが残る場合、成果物は `draft` または `review` とし、`approved` にしない。

## 6. 低解像度画像の扱い

- 読める構造と読める文字だけを採用する。
- 判読不能文字を文脈で補完して確定情報にしない。
- 原本、高解像度版、PowerPoint、PDF等の有無を一度だけ確認する。
- 原本がない場合は「厳密な転記」ではなく「意味構造の暫定再設計」と明記する。
